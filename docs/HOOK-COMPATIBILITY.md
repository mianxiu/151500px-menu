# Hook 迁移与验收

## 能否换电脑

当前图层查找使用 Ctrl+F；裸 F 留给 PS。原单 F 线程内消费仍只是隔离原型，没有启用到生产。

当前 hook 没有绑定开发机的用户名、盘符、硬件 ID 或 Photoshop 内存偏移。正常迁移使用完整发行包和目标机器自己的配置／UXP 安装，目标进程、窗口和 UI 线程在运行时发现；不需要复制开发机 Python、编译器或源码目录。

这表示具备迁移设计，不表示任意电脑均已验收。公开版与本机候选以 Versions／TODO 为准；2026-11-08 本机已更新318／UXP0.3.96，前一验收基线为0.4.317／UXP0.3.95，PS24.0.1，其他机器不能由这份证据代替。

| 层 | 实现与迁移条件 | 主要失败方向 |
| --- | --- | --- |
| 快捷键 | `native/HotkeyHost.cpp` 的 `WH_KEYBOARD_LL`／`WH_MOUSE_LL`；运行时核验 PS 身份，读取已发布输入证据 | 权限／桌面会话、远程注入标记、钩子超时或被移除、输入证据失鲜 |
| PS 线程内 IME | `backend/input_context.py` 从资源目录提取并按哈希保存 `InputContext.dll`，附着目标 UI 线程的 `WH_GETMESSAGE`／`WH_CALLWNDPROC` | DLL 架构不匹配、PS 提权、注入被企业策略阻止、旧 DLL 已驻留、窗口类别变化 |
| 输入识别 | 核验 `Photoshop`／根内 `PSViewC`、标准输入控件、画布编辑世代，并结合 UIA／UXP | 自绘控件或 IME 差异、异步事件乱序、工具读取失败、编辑退出后的首键竞态 |
| 查找菜单 | 原生 F 判断→后台忙碌／目标校验→菜单准备／呈现 | 接到了 F 却因保护拒绝、目标失鲜、菜单／前台交接、渲染失败 |

位数须匹配。现有构建为 Windows x64，不把 ARM64 或 32 位环境列为已支持。使用标准用户、同一交互桌面运行；不把“全部以管理员运行”作为通用修复，不自动关闭安全软件或改变系统策略。线程内代码仍依赖 PS 的窗口／编辑行为，因此并非完全与 PS 版本无关。

依据：[线程钩子与 DLL 架构要求](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowshookexw)、[低级钩子消息线程与超时](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)。`WH_KEYBOARD` 在取键盘消息时回调，`HC_NOREMOVE` 可能重复观察尚未移除的消息；这不等于已经消费该键。[KeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/keyboardproc)

## 在另一台电脑开始

1. 下载同一完整版本，核对安装包 SHA256；保持目标机器自己的配置与诊断，不复制开发机的 `.runtime`、UXP 请求邮箱、pending／owned 或恢复记录。备份已有配置及分层原稿；旧机器未知请求先保留，不能通过搬目录把它结清。
2. 用目标机器普通用户安装／启动主程序与内置 UXP。后台核对主程序版本、原生组件、已安装及 PS 实际加载的 UXP 版本；同次只使用一个明确 PS 实例。更新内嵌 DLL 后，如已驻留旧版本，先检查任务和备份，再正常重启 PS，不能只比较磁盘 DLL。
3. 在“运行状态”导出综合诊断，记录 Windows 构建、CPU／内存／GPU、PS 版本、IME 名称／版本、进程权限、远程／本地、当前布局和组件哈希。先用隔离小文档，确认没有 busy／恢复未知，再做下表。
4. 每台机器单独保存原始结果；写清版本、场景、预期、实际、样本数、误吞／漏拦／重复／失鲜／拒绝／未知数量。失败和中止样本不能删除或计入通过。CPU 限制在 finally 恢复，原稿不参加输入实验。

## 验收矩阵与顺序

按层推进；早期门禁失败就定位该层，不连续重发 F 或宿主写请求。建议每个短序列先做 3 次有效样本，再进行持续批次；这是起始验收量，不是可靠性保证。

| 阶段 | 必测场景 | 通过标准 |
| --- | --- | --- |
| 构建／协议 | 原生状态机、负 hook code、`HC_NOREMOVE`／重复取消息、重复键、消息投递失败、身份／nonce／世代不符、旧结果晚到、部分安装失败 | 不误消费、不重复执行、不让旧证据批准新请求；失败有证据，能确认退出 |
| 首次部署 | 新 Windows 用户首次启动、含中文／空格路径、无 Python／编译器、安装／更新／卸载、重启 PS | 资源齐全、版本一致、配置保留；安装不等于实际加载 |
| 快捷键正向 | 中文 IME 开启的非输入区域；F→Esc→立即F、快速 F、按住／重复／松开、Caps 短按／长按／中心取消 | 每次明确动作最多一次，按下与松开归属一致；空白／中心不执行 |
| 输入保护 | 新建及已有文字、图层／组重命名及 Tab、数值框、搜索、插件输入框、PS 原生对话框、未知自绘控件 | 中文首字与选词正常；输入及未知不抢 F，不把无 caret 当作可执行依据 |
| 编辑切换 | 组字时 F／Esc；无组字 Esc、Ctrl+Enter、小键盘 Enter 退出后立即 F／M／V；点击和双击进编辑 | 先确认真正进入／退出编辑；退出首键有效，文本无多字／丢字，布局和所选 IME 不变 |
| 前台／焦点 | PS↔其他应用、任务栏／Alt+Tab、自有菜单返回、浮动对话框、多 PS 实例 | 其他应用不吞键、不改 IME；目标不明拒绝；旧菜单不能重开或执行 |
| 任务／恢复 | busy、超时、历史未知、失联、服务正常退出／重启、PS 正常退出、旧 DLL／版本不匹配 | 忙碌拒绝不排队；未知不重发不伪造终态；IME 恢复、卸钩有确认，不强杀 PS |
| 低配／正常 | 同机同 PS／文档／序列：先双逻辑处理器＋Below Normal 短批次，再正常配置 | 两组分别记录，恢复亲和性／优先级；不把 CPU 限制等同低内存或集显 |
| 时间／持续 | 冷启动首次、闲置 5／30 分钟首键、热态连续、长时间使用、睡眠／会话恢复 | 每组有效样本独立；记录 hook 健康／丢失／失败数量及恢复行为，不能用热态替代冷态 |
| 跨环境 | 本机与原故障 PS25.5.1；Win10／Win11、计划支持的 PS 版本；微软拼音／其他用户实际 IME；远程、PS 提权、受管电脑 | 每个组合独立结论；权限阻止时明确不可用／安全让行，不靠切布局或关安全策略“通过” |

“脚本／夹具”“真实 PS 接口”“合成键鼠”“实体键鼠”分开记录。三档 PS 字号、命中／取消按 UI 改动范围补验，不默认每次四主题或全仓回归。涉及写操作须另核验真实目标、原内容、一次撤销和临时文档收尾。

性能优化另存同口径基线；冷／闲置／热态分别给出样本数、中位／P95／最大、前→后毫秒值及绝对／百分比变化。回调处理、跨进程转发、菜单首帧与实体按键到屏幕延迟是不同指标；没有可比样本就不报加速。

## 失败时先看哪一层

1. 看 `hook.health`／配置确认、组件版本和 PS 进程／线程身份。没有 F 原始到达证据时，优先检查权限、会话、钩子健康；不要先改菜单。
2. 有 F 到达但没有动作，看 `search.trace` 的 blocked、输入状态／世代／焦点、新鲜度和拒绝原因。保护拒绝不能当钩子漏收；也不能删保护来让它通过。
3. 有查找动作但不显示，看后台任务接受、菜单会话／准备确认、真实窗口可见与首帧。窗口存在不等于已绘制，后台返回成功也不等于实体交互通过。
4. 仅中文或编辑退出失败时，再比较线程内取消息、IME／组字、编辑进入／退出与全局 F 的时序。缺少哪段就单独采集；未知只核对原请求，不补发原键或重放操作。

## F 线程内原型的当前实施范围

`tools/ThreadFProbe.cpp` 是独立、只观察的诊断 DLL，不进入产品包，也不替换运行中的 `InputContext.dll`。它沿用项目按 UI 线程附着及本地有界记录的方式；核验 PS 名称、根窗口和线程后安装 `WH_KEYBOARD`、`WH_GETMESSAGE`、`WH_CALLWNDPROC`。回调只记录 F／PROCESSKEY、F 字符是否出现、焦点／布局、画布世代及 IME 事件类别，不读取正文、候选内容，不修改 IMM／TSF，也不执行后台动作。

```powershell
# 项目根目录；已安装 MinGW g++，只构建测试工具
./tools/build-thread-f-probe.ps1 -Low
.runtime/thread-f-probe/build/test-thread-f-probe.exe
python -m unittest tests.test_thread_f_probe -v
# 和 PS 相同的普通用户权限；先收起菜单并确认空闲
python tools/thread-f-probe.py --seconds 20
```

观察器不会自动发送键鼠。原始 TSV 与 `capture.json` 写在新建的 `.runtime/thread-f-probe/<运行标识>/`，含 DLL 哈希、PID／线程／根窗口、两端完整性等级、启动／停止状态、事件及溢出计数。`stage=1` 是线程键盘钩子（message 0／3 分别为 ACTION／NOREMOVE），2／3 是队列保留／移除，4 是发送消息；flags 保留重复次数、先前按下及松开位，PROCESSKEY 另带 `0x1000000`。`entry_newer` 只比较已发布进入／退出时间，不能据此授权输入操作。无事件不能证明安装失败或迁移成功。

工具源码均在 `tools/`，不依赖被忽略的历史 `tools/ime-probe/` 实验目录。DLL 载入 PS 后不能覆盖重建；下一次构建使用新的 `-OutputDirectory`，运行时用 `--dll` 指向对应产物，或等 PS 正常退出后再重建原路径。本轮最终构建在 `.runtime/thread-f-probe/final-build/`；旧路径一次因驻留文件占用构建失败，未强卸 DLL。

服务现有全局 F 可能先消费非输入区域的 F，观察器因此看不到它；不能为了填样本直接停掉全部保护。下一阶段需要有确认和回收机制的独占消费交接，先在隔离目标验证。当前分析结果固定保留 `migration_gate=not-validated`，不会由数量自动宣称可靠消费。

控制进程退出或最长 30 秒后自动卸除内部三钩子；控制器独立核对停止及加载钩子卸除后才导出。超时／卸钩未知保留原身份与日志，不重发原启动，不强卸 DLL。控制窗口的代码被固定到 PS 生命周期，停止后 DLL 仍驻留但钩子不活动；为避免把旧构建当新构建，同一 PS 生命周期仅一次观察，下一批需正常重启 PS（先检查任务及原稿备份）。

2026-11-08：最终构建的原生夹具在低 CPU／正常配置通过；3 项分析及4项受影响打包／数据路径测试通过。真实 PS24.0.1 三钩子安装、20 秒有界观察、停止与加载钩子卸除已确认；本轮 F 有效样本 **0**，丢失计数 0。最终自包含控制器另核验进程创建身份、路径、两端权限及拒绝重复安装，未重装原探针。电脑控制工具两次报 PS 窗口所有者不符，未发送任何键鼠。该结果只验证观察器生命周期，**时序／独占消费／真实输入／性能门禁尚未通过**，观察当时生产为317；当前318已按用户要求改Ctrl+F，消费原型仍未启用。证据 `.runtime/thread-f-probe/live-observe-1/capture.json`、`final-controller-precheck/capture.json`。完整迁移条件见[输入法评估中的 F 计划](INPUT-LANGUAGE-ASSESSMENT.md#f-键线程内拦截验证计划)。

## F 独占消费的隔离原型

继续实施后新增 `native/ThreadFKey.h` 和 `tools/test-thread-f-route.cpp`。消费核心只被测试工具引用，尚未进入 HotkeyHost、InputContext 生产构建或后端查找转发。它以根窗口、焦点、nonce 和输入世代共同约束首个 F；通知投递成功才消费，投递失败即撤销资格并放行，不补发、不自动重试。`HC_NOREMOVE` 不建立消费归属、不通知；未接管的重复／松开及修改键组合放行。接管后只发一次通知，并消费配对重复／松开；停止先关闭新按下资格，已接管的松开完成前不能交还归属。

纯状态机对照将两条消费路径按“全局→线程”顺序串联：旧路径已消费的按下即使中途发布线程路径，其重复／松开仍属于旧路径；新一轮才由线程接管；线程完成松开后才撤回发布。低 CPU／正常配置各1000轮对照通过。这是算法夹具，**尚未验证生产两进程握手、Windows 真实键流或 PS IME 时序**。

原生窗口夹具直接复用现有 `native/InputContext.cpp`，只在自己的进程创建 `Photoshop`／`PSViewC` 类测试窗口和标准 Edit；不向真实 PS 注入此消费原型。它核验真实 IMM 关联恢复、输入／画布编辑及组字消息保护、原生画布世代变化和异步 PostMessage 通知。焦点离开再返回同一窗口也必须轮换独立输入世代，旧通知因此被拒；停止后的待处理通知也拒绝。直接调用 F 回调模拟按下／重复／松开，不能当作真实键盘消息或中文候选输入。

```powershell
./tools/build-thread-f-route.ps1 -Low
.runtime/thread-f-route/build/test-thread-f-route.exe --low --window-check .runtime/thread-f-route/window-low.log
.runtime/thread-f-route/build/test-thread-f-route.exe --window-check .runtime/thread-f-route/window-normal.log
# 独立的真实按键验证窗口；60秒后正常收尾，仍有已消费按键时先等松开
.runtime/thread-f-route/build/test-thread-f-route.exe --low --interactive .runtime/thread-f-route/interactive-low.log
```

交互窗口上方为空白非输入区域，下方为标准输入框。上方按 F 应只增加一项 sent／accepted，不把按键传到窗口；进入下方输入框不增加这两项；返回上方后新 F 才重新接管。回调只在固定内存记录事件，结束后导出；不在回调内写文件。日志注明 `samples=direct-callback` 或 `windows-hook`，记录实际 CPU 亲和性／优先级、布局、通知／拒绝和正常退出／原关联恢复。回调耗时不是实体按键延迟，当前没有同口径317速度基线。

本轮最终低 CPU／正常原生窗口检查均通过，输入布局保持 `0x08040804`；每组构造3个通知，其中1个正常接受、旧焦点通知和停止后通知各拒绝1个。隔离交互窗口在电脑控制访问授权超时后自动正常退出，恢复关联及卸钩通过，但键盘回调有效样本0，不计交互通过。原始记录：`.runtime/thread-f-route/window-low-final.log`、`window-normal-final.log`、`interactive-low.log`。

为排除旧驻留 DLL／窗口记录影响，本轮已保存并核验最新分层原稿，正常退出旧 PS 后通过产品现有启动请求建立新会话；启动未就绪时的第一次 COM 获取明确失败、未执行恢复，待原启动请求成功且 UXP 就绪后才恢复。原稿图层及文字核对一致，文档身份随新会话更新；不保留旧撤销历史。重启后的 PS 窗口仍报所有者不符，未发送按键。备份与恢复证据 `.local/recovery/thread-f-prototype/`、`.runtime/thread-f-prototype/`。

下一门禁仍是317同口径的真实 F／中文编辑时序、PS 原生输入保护及独占消费交接；随后才接入后端查找入口、冻结构建和实际服务。当前没有可用的电脑控制 PS 窗口绑定，继续自动发送或改用未经核验的键鼠通道不能补足该门禁。

结论边界：

- 非 PS 前台的钩子判定路径从约 49–56 µs 降到 2–6 µs，是本次 §3B 的目标；原因是钩子不再在每次事件上打开/查询前台进程，而是读消息线程发布的快照。
- PS 前台时基线本来就走正缓存（不 `OpenProcess`），所以中位/P95 基本持平；低 CPU PS 按键 P95 +34.3% 和正常 PS 鼠标最大 763 µs 是单批观测，不能确定稳定变化，也不据此声称整体提升。正常 PS 按键 P95 -25.6% 也不单独当作优化证据。
- CPU 增量有升有降，未显示稳定收益；没有把它写成提速。
- 这是**钩子回调耗时**，不是实体按键到屏幕延迟，也不是首帧/端到端时延。
