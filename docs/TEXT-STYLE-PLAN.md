# 文字样式读取与一致预览方案

状态：2026-11-10。普通文字层的单窗口列表编辑与PS悬挂续行已在288本机闭环；323／UXP100候选已修正新智能对象的浏览器重排问题，用PS原生PDF显示并保留文字／样式源，完成低CPU与正常配置的接口验收。候选尚未公开分发，步骤及边界见[文字对象](TEXT-VECTOR-OBJECTS.md)，公开状态见[Wiki Versions](https://github.com/mianxiu/151500px-menu/wiki/Versions)。

287曾有整体不可用反馈，旧实验与失败记录保留。当前完成的是文字对象承载与正文重新编辑；独立画布、准确画布预览、通用字符／段落控件和双击接管仍未实现，不能把承载部分算作整个排版编辑器。

## 已确认的新方向

2026-11-10补充 TODO：将列表从现有文本工具中拆出，纳入类似矢量设计工具的独立矢量文本工具，统一编辑字体、字号、字距、行距、段前／段后间距以及字符／段落样式。列表和样式共用草稿与PS排版链路；替代工具实际可用前保留现有列表入口。本次只记录需求，不代表已拆分或已提供样式控件。

用户要求采用类似液化的独立画布编辑页：读取当前画布作为上下文，支持缩放和平移；在原有文字位置编辑换行、列表、字体、字符和段落属性，查找替换暂不纳入新编辑页。用户已选择写回智能对象时保留可编辑文字和样式，进一步要求具备类似Illustrator矢量智能对象的放大能力。

据此，**可编辑源内容与矢量显示结果必须同时保留**。不能把文字转曲后丢弃正文，也不能仅把文字层转为普通PSB智能对象就宣称任意放大无损。准确排版仍由PS完成，不另用浏览器或DirectWrite重排并声称等同PS。

### 承载实验与结论

本机PS24.0.1在低CPU／正常配置分别验证同一组中英文文字，均在自建隔离文档内进行：

| 路线 | 实测结果 | 判断 |
| --- | --- | --- |
| Photoshop PDF，保留PS编辑能力 | PDF包含文字绘制指令及嵌入字体；重新打开恢复可编辑文字层；置入后放大8倍出现明显位图模糊 | 单一文件同时有编辑数据与PDF矢量内容，不等于PS会按矢量置入，不能采用此路线保证放大质量 |
| PDF，不保留PS私有编辑数据 | PDF包含文字绘制指令及嵌入字体；置入智能对象后放大8倍字形保持清晰 | 可作为矢量显示候选，但自身不能代替可编辑源，必须另外保留源内容 |

两条路线与直接放大的PS原生文字均不是逐像素相同；实验中对象定位、抗锯齿和渲染差异尚未分离，不能据此承诺像素一致或所有字号／字体／宿主可无损。证据为`.runtime/vector287-proof2/report.json`、`vector287-proof3/report.json`及原始PDF／BMP。源文档内容、历史、选择和保存状态保持，临时文档已关闭。首轮错误枚举的原始未知记录及匹配的脚本执行退出证据保留在`vector287-proof/failed-enumeration-evidence`与`cleanup-audit.json`，没有重发原请求。

287已采用“嵌入矢量PDF＋同图层XMP中的原生文字／样式模型”，验证PSD保存重开、改名、同／跨文档复制及独立更新。PDF内自定义元数据在本机嵌入时被PS清除，因此不作为唯一源容器；完整备份必须保存PSD，单独导出的PDF只有显示内容。更新先核对源模型和实际嵌入PDF校验值，不用本机缓存、临时路径或图层名找回正文。原生PSB文字层、字体文件随对象打包及原生双击接管未实现。证据与限制见[矢量文字对象](TEXT-VECTOR-OBJECTS.md)。

### 编辑页的数据与交互

- 打开时只读捕获真实文档／图层／会话、画布尺寸、分辨率、色彩配置、文字变换、文本框及完整样式范围。背景只在打开或明确刷新时读取，不随每次键入重新读取全画布；原生矢量文字单独处理，不把画布截图当成文字源。
- 工具控件沿用Caps共享规范；画布中的文档文字使用其真实字号与坐标。字符选区、当前段落及整层三种作用范围明确；混合值保持混合，未知字段不被第一段默认值覆盖。
- 字符和段落选项建立按实际宿主能力验证的字段表，覆盖PS可读取和可写的选项；每项包含类型、单位、范围、默认／继承、适用范围和写后读回。不能用一个裸JSON输入框冒充完整面板，也不能把DOM没有暴露的字段直接丢弃。当前公开DOM并不代表旧版已有全部能力，旧版需逐项验证描述符路径。
- 本地只合并最新草稿，输入和中文组合期间不逐键导出／取图。准确字形显示由同一份PS排版结果派生，平移和缩放只重用当前显示缓存；取图或矢量更新未完成时明确标记旧结果，不允许确认过时草稿。
- 列表使用真正段落悬挂缩进和制表位，自动折行后的续行对齐正文；不向正文插入显示换行或空格。288候选已在普通文字层实现此点，实际入口与验证范围见TODO及列表说明。
- 确认后以相同源版本生成矢量显示并写入／更新对象，核验源与结果关联及父文档的位置、变换和目标。取消保持原稿，一次撤销恢复源与显示；未知修改或回滚保留保护，不重发。复制实例的共享关系必须明确，不能无意更新其他实例。

### 旧版与显示边界

完整画布背景读取与矢量字形读取是两种能力。现代宿主可评估`imaging.getPixels`读取合成画布，不能因为字体描述可读就认定背景图也可静默获得。本机PS24.0.1缺少该接口；旧版背景的静默读取仍待验证，不回退到闪烁的新建预览文档或截取被其他窗口遮挡的屏幕。用户明确进入独立编辑工作区与后台偷偷新建预览文档须区分，但前者也必须有确定的取消与收尾。

矢量内容可由PS按目标尺寸重新栅格化，不意味着PS文档和PNG具有无限像素。普通文字、图层样式、位图效果、字体缺失或不可嵌入字体需分别说明，不能把文字样本成功推广为所有内容都为矢量。PDF支持矢量和位图混合，必须检查实际输出，不能仅凭扩展名开放“无损缩放”。

依据：[Adobe置入AI／PDF智能对象](https://helpx.adobe.com/photoshop/desktop/app-integrations/place-illustrator-files-or-pdf-in-photoshop.html)、[Photoshop PDF保存与编辑能力](https://helpx.adobe.com/photoshop/desktop/save-and-export/save-files/save-as-photoshop-pdf.html)、[直接像素读取](https://developer.adobe.com/photoshop/uxp/2022/ps_reference/media/imaging/)。文档支持能力是路线依据，具体旧版行为以上述隔离实测为准。

## 当前差距

UXP的`createTextTools.descriptor`已经读取完整`textKey`、`textStyleRange`和`paragraphStyleRange`，并保留在当前目标快照中；`read()`交给面板的只有文字、名称、目标和版本身份。`mappedText`按来源映射原样式，`stylesMatch`在写后校验字符和段落样式，现阶段没有字体／行距编辑协议。

原生`MenuControls::multiline/textPreview`用工具的Body字号和面板宽度排版。283的列表续行对齐也只是本地显示，不代表PS的原文本框宽度、字体、字距、行距、缩进和排版引擎。用相同字体名称绘制，仍不能把本地排版称为PS准确预览。

## 推荐实现

### 读取与草稿

- 在现有文字读取中投影样式信息，不为每次键入重新读取PS或枚举全部字体。原始描述保留在执行端；面板接收有界的可编辑值、样式范围和能力标记。
- 字符范围包括字体的PostScript标识、字号、颜色、自动／固定行距、字距、缩放和基线；段落范围包括对齐、首行／左右缩进、段前／段后及自动行距比例。同时保留点文字／段落文字、文本框、方向、变换、文档DPI和原有排版设置。
- 多字体、多字号或多段落值显示“混合”，不能取第一段的值代表整个图层。调整明确作用于字符选区、当前段落或整层，未修改字段及未知字段保持原值。
- UTF-8编辑选区与PS的UTF-16范围在边界转换。界面单位与宿主描述单位分开；显式换算点／像素与DPI，自动行距和固定行距不能混成一个数值。
- 所有预览和确认引用同一目标快照及草稿版本。改变文字、样式、选区作用范围或目标后，旧预览不得继续确认。

### 准确预览由PS完成

优先实现明确开启的“PS画布预览”，沿用本项目颜色／羽化预览的目标绑定、单事务、取消和未知结果保护；这是待验证的复用方向，不代表现有颜色执行器可直接处理文字。

1. 只读打开与本地内容处理不修改PS。用户明确开启画布预览后，才进入可取消的文字预览事务；保持原有PS前台／输入保护。
2. 由PS对真实目标应用当前文字及样式草稿并排版。输入／中文组合期间不逐键发宿主命令，静置后合并预览值；一次只处理一个预览，过时返回不用，不积压修改任务。具体节奏以旧版低CPU实测决定，不承诺180ms内完成PS排版。
3. 读回并验证当前文字、字符／段落样式、文本框与目标；只有最新草稿得到可信结果，才显示“PS预览已更新”。不以请求已发送或本地动画代替成功。
4. 确认提交已经验证的同一份PS预览状态，不在确认时另算另一套样式。一次撤销恢复原文和样式；取消必须核验恢复。修改或恢复未知时保留保护，不重发、不假定已恢复。

PS画布使用同一宿主引擎与文档排版条件，是本方案确保预览与提交一致的依据。准确面板图片是后续可选项：仅在静默直接像素读取已实测可用时，显示PS生成的图像；图片按比例缩放，不随面板宽度重新排字。不支持时保留可用的画布预览，不开放准确图片按钮，不新建文档、不导出PNG，也不用本地近似排版冒充准确结果。

### 内容处理与样式排版

现有入口先区分“内容处理”和“样式排版”。编辑、查找替换、整理、拆分、列表继续提供快速的本地内容处理；字体、行距、段落缩进进入样式排版。普通水平左对齐文字列表已用PS段落属性实现续行对齐；更广排版能力仍按本方案推进，不能用本地补空格预览代替PS效果。

UI控件继续遵循共享字体角色和MenuControls；文档文字的字体／行距是被编辑的内容，不改变工具栏和说明文字的UI字号。以后拆出独立面板时，复用同一快照、草稿和事务，不复制另一套样式映射或预览写入逻辑。

## 候选：双击重新编辑的列表对象

285已先闭环原生文字层＋XMP列表选项：保存重开、复制、原生正文重新读取及一次撤销通过。287另增加可重新编辑的矢量智能对象；两者均从Caps文本工具／文字源打开，双击接管尚未实现。数据与实测范围见[列表选项](TEXT-LIST-OBJECTS.md)和[矢量文字对象](TEXT-VECTOR-OBJECTS.md)。

本机PS24.0.1的下一步只读检查已确认Layers面板原生身份。UIA Raw View共返回16个控件，遍历未截断；能读取面板、滚动条和顶部输入／筛选控件，但没有返回图层行、文字缩略图、蒙版的独立区域。现有PanelContext也只识别整块图层区域，不能据此安全判断缩略图双击。未启用拦截或猜测固定像素命中；需要另一条可核验的精确命中来源，或更窄的已确认交互方案。证据`.runtime/list285-accessibility.json`及`layers285-hwnd.json`；此结论仅覆盖该宿主与该接口，不代表所有PS没有其他方案。

这是2026-10-28后续可行性问题，尚未选择或实现，不替代前面的样式读取与准确预览。现有公开UXP接口未提供注册新LayerKind或可取消的智能对象双击前置回调；事件通知不能作为已拦住原生动作的证据。本项目已有Windows原生鼠标hook，可以评估复用，但尚未验证图层缩略图的准确命中及双击接管。

| 承载方式 | 可提供的体验与代价 |
| --- | --- |
| 原生文字层＋列表标记 | 仍是可编辑文字，保存列表层级／编号和样式数据，由插件识别为逻辑“列表对象”；最贴近现有文字读写，优先评估 |
| 嵌入式智能对象＋列表源数据 | 可把多个文字层作为一个可复用对象；插件编辑列表，未运行插件时仍保留普通智能对象和内部文字。读取／更新内部内容、实例共享与跨文档恢复更复杂，需要独立验证 |

拟议交互为：只对已确认的列表对象缩略图双击打开同一个列表／样式编辑器，普通图层、重命名、蒙版、图层样式及其他智能对象保留默认行为。保留Caps／按钮入口作为识别不可靠时的可用路径；不先打开PSB再立刻关掉来伪装无闪烁接管。

实现前必须验证：

- 持久标记和有版本的列表数据随PSD保存，不能仅依赖图层名称、临时layerID或本机缓存；保存重开、改名、复制／跨文档复制、撤销／重做都要保持正确关联。不能未经实测就认定某个元数据字段支持一次撤销；不覆盖其他插件数据，也不执行文档中携带的代码。
- 原生拦截在PS执行默认动作之前完成，且依据真实缩略图区域和新鲜对象身份。hook回调只作有界快速判断，不等待COM／UXP或解析大段数据；身份、命中或输入状态不确定时不拦截。还要覆盖列表滚动、缩略图尺寸、DPI、快速换层和完整按下／松开配对。
- 智能对象方案要验证源数据、内部文字与父文档画面同步，确认／取消及一次撤销完整恢复；共享实例与“通过拷贝新建”不得混淆。原生打开PSB及更新内部内容是否会闪烁也属于门槛，未通过不能声称无切换编辑。
- 插件关闭或没有安装时仍能查看和按PS默认方式编辑对象，不依赖自定义文件关联。PS原生类型／图标不会仅因列表标记而变成新类型；插件自己的识别与筛选需另作明确区分。

依据：[UXP LayerKind枚举](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/modules/constants)、[动作通知接口](https://developer.adobe.com/photoshop/uxp/2022/ps_reference/media/photoshopaction/)。以上是当前公开接口范围的核对与方案判断，不是对全部C++ SDK能力的否定，也不是双击接管的实测结论。

## 分步验收

1. **先读样式**：从现有快照显示字体、字号、行距和段落缩进，包括混合状态；读取不改变PS内容、选择或历史。优先在本机PS24.0.1验证旧版描述路径，不依赖24.1新增DOM接口才能使用。
2. **再写样式**：先闭环单层字体／字号／行距／缩进，保留其余样式及文本框；验证72／300DPI、点／段落文字、自动／固定行距、中英文及混合样式、缺失字体拒绝和一次撤销。之后扩展字符选区、多级列表及更多排版参数。
3. **再开准确预览**：验证旧版低CPU／正常配置中的画布刷新、最新草稿与确认状态一致、取消精确恢复、前台／输入／目标变化及未知结果保护；仅有本地渲染图或接口文档不能算通过。
4. **最后评估面板图片与独立入口**：按实际能力开放，分别记录宿主往返、排版／取图耗时和实体显示延迟。不为图片预览牺牲旧版稳定性，不先承诺跨PS版本像素完全一致。

第一步完成前不宣传已支持读取／调整字体和行距；实际文字预览事务完成前，不把现有纯文字结果称为所见即所得。

## 官方依据与实现边界

- [TextItem](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/textitem)：字符／段落属性及24.1 DOM门槛，部分像素数值与文档DPI有关；旧版复用项目现有描述读写路径，仍需实测。
- [ParagraphStyle](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/paragraphstyle)：段落缩进等属性；实际字段、单位和继承关系以宿主读回为准。
- [模态执行与历史事务](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/executeasmodal)：`suspendHistory/resumeHistory`与提交／回滚；模态结束会自动处理未结束历史，不能跨任意模态调用保存一个悬空事务。
- [Imaging API](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging)：直接图层／文档取图、目标尺寸、颜色转换与资源释放；取图能力不代表已支持安全的文字草稿预览。
