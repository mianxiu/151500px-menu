# 聚焦所选图层

在图层面板选择目标后按 **F**，将画布移到所选内容并自动调整缩放。**Ctrl+F** 仍打开图层查找，Caps+F 仍是图层样式。适用公开版本见 [Wiki Versions](https://github.com/mianxiu/151500px-menu/wiki/Versions)。

## 使用

1. 更新主程序并正常重启 PS，确认实际加载 UXP0.3.99。
2. 在 PS 中选择一个图层、一个组或多个图层／组，退出文字、数值或重命名输入。
3. 在 PS 工作区按 F。多选按内容边界的并集聚焦；原生“适合图层到屏幕”完成平移与缩放，最高400%，最低0.01%。锁定目标也可聚焦，不解锁、不改变图层选择或内容。
4. 短按后，PS原生边界约显示0.5秒便关闭，聚焦后的视图保留。长按F（至少250毫秒）临时聚焦，按住期间持续显示原生蓝框（颜色沿用PS设置），松开关闭边框并恢复原缩放与位置；按住时Esc也可取消。
5. 边界颜色沿用PS设置，不强制为红色；智能参考线仍由PS原生移动／Ctrl交互显示，不保持Ctrl按下。临时开启的“额外内容”恢复原值；“图层边缘”在结束后关闭，包括旧319遗留的开启状态。

F在PS工作区使用；已固定Caps菜单中的f和Caps+F仍保留图层样式。Shift／Alt／Win组合和其他应用前台不触发聚焦。输入、未知、忙碌或目标变化时拒绝，不排队。最多128个选中目标，隐藏目标或隐藏父组须先显示；没有内容边界的空图层明确拒绝。混合选择中的空边界不参与并集。

## 当前限制

- 按住时占用同一次视图事务，不接受其他插件操作。松键仍属于原手势，不排队、不创建第二次恢复请求。提交前已松开的长按不闪现迟到的聚焦；前台离开或失联会结束临时聚焦；正常按住不再设30秒上限。原文档或会话改变时，不对新文档执行恢复；恢复未确认则保留原请求保护。
- 321将裸F交给PS消息线程，在选层消息处理后识别真实非输入区；已核验非输入区即消费，忙碌、目标拒绝或投递失败也不回放PS原生F。文字、重命名、数值及未知区域继续让行。Ctrl+F与Caps+F保持原分工。需正常重启PS加载匹配的原生组件；线程绑定未建立或其他机器的窗口结构尚未核验时，不承诺全局拦截。偶发IME候选的全部来源仍未穷尽。
- PS菜单树的勾选值存在缓存，只用它定位内置命令；执行与恢复以实时 `uiInfo/getCommandEnabled` 的读回为准。该状态接口不可用或原生菜单无法识别时拒绝，不猜测状态或反复切换。
- 图层内容／选择／历史保持，聚焦属于视图操作，不新增撤销步骤。失败会尝试恢复原缩放、中心及显示状态，恢复未知时保留原请求并阻止重发。

## 验证边界

321／UXP99证据位于 `.runtime/focus-321/`。最终第四候选：PS24.0.1低CPU（双逻辑处理器／Below Normal）及正常配置各5项真实合成F手势、Ctrl+F通过，每次均验证新的PS线程消费记录；短按、长按、Esc、多选、松键视图恢复及边框关闭保持选择／历史。长按实屏确认蓝框持续绘制。快速选层采用实际图层列表窗口消息紧接SendInput F，两档各6次，逐次核验选择实际变化、新目标ID、PS线程按下记录与实时屏幕模式不变；各补空层失败不触发原生F，以及真实Edit／caret编辑状态F不产生聚焦任务。该输入保护证据不等同于中文组字正文／候选全项验收。

同一UXP99的隔离接口两档各12项通过，含组、锁定、隐藏／空目标、文字、租约失联及提前松键；最终改动只涉及全局F松开分工，复用这些未受影响的接口结果。86项受影响Python、Node视图模型、原生快捷键／PS线程夹具及实际启动JSON端点校验通过；新鲜健康长按超过30秒由模型覆盖。最终冻结与运行组件匹配，原稿7层及文字、配置和CPU资源恢复。EXE启停／重启与公开分发结果见发行记录。

原始失败未删除：启动后非输入尚未就绪、前台切换中止、点击坐标未命中、启动消息遗漏端点导致仍走旧路径、全局吞掉原生配对松开导致后续按下被判重复，及原生长夹具前台交接失败均保留。启动消息及松开分工已修复并由最终批次覆盖；历史候选通过不替代最终按键结果。未验实体鼠标／键盘手感、从其他应用点击激活后立即F、快速多选／组的鼠标序列、全部IME／窗口结构／其他PS和跨机、长期与冷启动可靠性；无性能或端到端加速声明。
