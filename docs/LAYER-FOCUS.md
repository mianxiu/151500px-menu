# 聚焦所选图层

在图层面板选择目标后按 **F**，将画布移到所选内容并自动调整缩放。**Ctrl+F** 仍打开图层查找，Caps+F 仍是图层样式。适用公开版本见 [Wiki Versions](https://github.com/mianxiu/151500px-menu/wiki/Versions)。

## 使用

1. 更新主程序并正常重启 PS，确认实际加载 UXP0.3.97。
2. 在 PS 中选择一个图层、一个组或多个图层／组，退出文字、数值或重命名输入。
3. 在 PS 工作区按 F。多选按内容边界的并集聚焦；原生“适合图层到屏幕”完成平移与缩放，最高400%，最低0.01%。锁定目标也可聚焦，不解锁、不改变图层选择或内容。
4. 显示 PS 原生“图层边缘”和“额外内容”。颜色沿用 PS 设置，不强制为红色；智能参考线仍由 PS 原生移动／Ctrl交互显示，不保持Ctrl按下。

F在PS工作区使用；已固定Caps菜单中的f和Caps+F仍保留图层样式。Shift／Alt／Win组合和其他应用前台不触发聚焦。输入、未知、忙碌或目标变化时拒绝，不排队。最多128个选中目标，隐藏目标或隐藏父组须先显示；没有内容边界的空图层明确拒绝。混合选择中的空边界不参与并集。

## 当前限制

- 当前版本保持原生边缘显示；用户要求的“F后描边自动消失”尚未纳入本版，下一步实现短暂提示后恢复原显示状态。现在可通过“视图 → 显示 → 图层边缘”手动关闭。
- 用户反馈 F 后偶发拼音候选，重新点击激活 PS 窗口后恢复。本版尚未修复，不视为输入法全面验收通过。
- PS菜单树的勾选值存在缓存，只用它定位内置命令；执行与恢复以实时 `uiInfo/getCommandEnabled` 的读回为准。该状态接口不可用或原生菜单无法识别时拒绝，不猜测状态或反复切换。
- 图层内容／选择／历史保持，聚焦属于视图操作，不新增撤销步骤。失败会尝试恢复原缩放、中心及显示状态，恢复未知时保留原请求并阻止重发。

## 验证边界

PS24.0.1实际319／UXP97：双逻辑处理器／Below Normal和正常配置的隔离接口各8项通过，覆盖单层、连续聚焦、多选、组、锁定组、隐藏／空目标拒绝和文字层，均核对历史与选择、资源及原稿恢复。低CPU真实SendInput批次完成连续F及Ctrl+F查找；正常配置中止批次的单层接口及连续F分项通过，不把外部前台切换后中止的整批改成通过。实屏确认原生边界与400%缩放。

原生热键自测、视图模型和59项受影响Python检查、冻结模块及EXE启停／重启通过。未测成的文字编辑F实机负向、多选F实体键盘、其他PS／Windows／输入法、长期／冷启动及跨机仍待验；输入与目标保护模型不冒充实体输入全项通过。证据 `.runtime/focus-319/`，含初期busy误拒绝、菜单缓存读回误判及夹具失败的原始记录；最终正向API样本 `api-low-1794153508259145000`、`api-normal-1794153520089636800`，低CPU键盘 `live-low-1794152798687533700`，正常分项 `live-normal-1794153067789865900`。
