# 故障机一键稳定性测试

208／UXP0.3.47扩展后台“运行状态 → 自动稳定性测试”。适用于定位图层识别越来越慢、长期加载或全灰；测试结果不能单独证明Win11、集显或CPU限频是根因。

## 操作

1. 安装当前主程序与内置UXP，保存文档并正常关闭／重开PS。确认后台的实际加载版本与已安装版本一致；只替换EXE不够。“标准／持续”模式至少需要UXP0.3.47，最低宿主为PS23.3。
2. 收起菜单，在后台选择“标准”（3轮、24次新增图层）或“持续”（10轮、80次新增图层），点击“一键开始测试”。保持PS运行且不要操作其文档，可以停留在后台管理窗口。默认使用电脑现有CPU、电源、GPU设置，不自动调整资源。
3. 结束后点击“导出测试报告”，得到JSON。报告同时自动保存在应用数据目录`stability-reports/`，包括每次运行的独立文件及`latest.json`。测试中、失败或中止后均可导出部分报告，不上传数据。
4. 如需停止，点击“停止后续测试”。当前宿主请求仍等待真实结果；预览沿原请求取消恢复，不强杀PS、不清除未知、不重复提交。测试中改变前台应用或测试文档／选择／历史会停止后续步骤。

忙碌、待核对任务、打开的菜单、只读诊断采集中或旧执行端会拒绝开始，不排队。测试期间菜单／快捷键修改也拒绝，不能插入测试序列。

## 208新增菜单循环

标准3轮包含54次生产菜单窗口显示／收起，持续10轮包含180次。每次使用新的菜单轮次和读取请求，核对匹配结果的原生接收、新鲜目标、按钮能力、窗口可见、非透明内容帧及收起；失败保留最后一份菜单状态。图层面板必须显示且能唯一识别，测试时会短暂显示只读菜单，不激活窗口、不发送键鼠，菜单内动作被阻止。可以继续停留在同一个后台／Codex窗口；切换应用、改变文档／选择／历史会停止后续步骤。

报告新增`last_menu_observation`、菜单步骤的`delivery`、`native_capabilities`、`native_content_visible`、`native_buttons_enabled`、菜单轮次与耗时，以及每秒和结束时的已有UXP心跳年龄／读取阶段。这是程序调用生产显示入口和接收链路，实体Caps、UU远程注入与按键到屏幕延迟仍不算自动验收。标准共117步，其中包含一次真实批量读取协议核对；PS不支持的预览仍单列跳过。

## 24.2.x读取兼容

208仅对PS24.2.x自动选择批量标量读取：文档ID、选择ID、模式／位深及最多4096条含组边界的图层记录；完整核对父组拓扑、顺序、类型、背景和锁定，再复用原能力算法，完成前重读选择身份。目标捕获也使用新鲜批量读取；不将缓存当作写前校验。缺失、损坏、超范围或未知类型数据保持禁用，不用不完整数据启用按钮。其他PS保留既有策略。

仅显式菜单颜色元数据在24.2.x使用短时只读模态范围，`timeOut:0`，不排队、不建历史、不修改文档；空闲图层读取不占模态。它针对已取得的24.2.0故障证据实现，发布时仍需原故障机验收，不能宣称已确认解决Win11／UHD730问题。相关一手报告：[24.2／24.3图层DOM读取延迟](https://forums.creativeclouddeveloper.com/t/long-time-to-access-api-data-in-photoshop-v-24/6072)。

## 自动覆盖

- 创建128×128px的隔离临时文档，包含矢量形状与像素图层；按插件会话、测试ID、文档ID、选择和历史检查点约束全部测试修改。
- 每轮在固定图层数量下交替修改标签8次，逐次读回；新增8个图层，并逐次读取新鲜选择；最多32层多选读取；闲置10秒后检查首次读取。
- 每轮颜色／羽化实时预览确认与取消各一次，每次两帧，核验真实读回、取消恢复和确认后一次撤销。PS版本不支持实时预览时，仅测试兼容单次提交和撤销，取消预览单列为`skipped`。
- 使用现有生产标签／增层／形状执行器和菜单选择读取协议，保留目标、能力、新鲜度、一次撤销、持久化请求及未知结果保护。临时文档准备、选层、撤销和关闭为内部固定操作，不提供任意脚本入口。
- 后台每秒采样总CPU及各逻辑处理器、PS进程CPU与内存、Windows频率／性能计数器、可用内存、磁盘队列和传输等待；记录OS、CPU、GPU驱动、电源计划和实际PS／UXP版本。失效或不可用的计数器明确列出，不记为0。
- 每步原始耗时、任务捕获／执行阶段、匹配请求的宿主进度、菜单接受／基础／完成阶段和新鲜度；汇总样本数、中位数、P95、最大值及前后段中位数。读取的总耗时包含自动测试自身的目标核对，以`timings_ms`区分PS读取阶段，不等于实体按键延迟。

成功时仅关闭本次确切拥有的临时文档，并恢复原活动文档；原文档不保存、不关闭、不修改。失败、中止或未知时保留临时文档及证据，不猜测执行是否停止。没有待核对任务时，可检查后手动关闭该测试文档，再开始新的独立测试；原请求结果未知时先沿后台“核对UXP任务结果”处理，不靠重启清除保护。插件重载后不按文档名认领或自动清理旧测试文档。

## 报告判读与边界

`phase=completed`表示计划的自动步骤结束，具体能力仍以每步的`passed`／`skipped`为准。`stopped`、`failed`、`interrupted`不能记为整套通过；后台重启不续跑。测试报告保留在本地，包含测试标识与机器配置，不包含凭据、原文档内容或名称。

低总CPU可能同时存在某个逻辑处理器繁忙，也可能是等待宿主／I/O；Windows报告的频率与性能计数器不是温度或限频原因证明。比较故障机与正常机时使用相同版本、同一测试模式，先保持各自设置不变；若做GPU／电源对照，每次只改一项并另存报告。

不自动验收实体Caps、UU远程注入、鼠标命中／手感、画布目视、真实大型用户文档内容、所有PS版本或硬件。小尺寸隔离文档的结果不能替代真实低内存／集显／大画布问题，CPU受限模拟也不能替代两台Win11／i5-12400／UHD730故障机。

## 实现依据

宿主修改使用Adobe规定的模态执行；历史与文档关闭使用其文档API：[Photoshop API](https://developer.adobe.com/photoshop/uxp/ps_reference)、[Document](https://developer.adobe.com/photoshop/uxp/ps_reference/classes/document/)。系统采样同时校验API返回值与计数器`CStatus`，无效数据不参与数值判断：[Microsoft PDH状态校验](https://learn.microsoft.com/en-us/windows/win32/perfctrs/checking-pdh-interface-return-values)。

本机交付验证和故障机待验状态见发行记录；下载入口为[最新版Release](https://github.com/mianxiu/151500px-menu/releases/latest)。

207验收中还暴露了后台读取剪贴板尺寸路径的进程堆异常，栈包含`GetClipboardData`／`GlobalSize`。读取现已串行化，并按剪贴板序号缓存已确认的尺寸，序号变化重新读取；不会复制像素或取消新建前的剪贴板身份检查。此项是并发防护，不能据此认定两台故障机具有相同根因。


## 维护用文字对象验收

323本机候选增加固定的`stability.start`／`text-object`模式，仅供维护接口调用，不新增“标准／持续”界面按钮。它通过服务现有COM执行线程调用PS，按72DPI点文字与300DPI段落文字验证生成、缩放移位副本更新、一次撤销重做、PSD重开与自建文档收尾。无需从外部打开JSX文件，也不修改PS的脚本警告或其他安全配置。执行中可能主动将焦点交回PS，现有产品前台保护继续生效。

使用原操作锁、PS／UXP会话和真实目标核验；每次原生请求保存原身份、完整代码、响应及执行退出状态。调用前报告发布失败只记录明确未开始；已提交而返回未知时阻止新的宿主操作，不重发、不自动清除保护。只关闭当前报告确切拥有的文档，失败时保留现场；有可信结果后可从既有收尾接口核验并关闭。测试不保存或关闭用户原稿。

本机低CPU／正常各10步已通过；其他宿主与实体输入仍待验。候选与公开状态见[Wiki Versions](https://github.com/mianxiu/151500px-menu/wiki/Versions)。

## 维护用原生颜色验收

326的固定`stability.start`／`color-native`模式验证CMYK／Lab／灰度8／16位的原生通道读取、写入与一次撤销；8位另核对原生渐变和启用描边。先双逻辑处理器／Below Normal，再正常配置。目标为该报告确切拥有的临时文档，执行后检查原稿历史、模式／配置和资源恢复；不接受外部脚本，不新增普通测试界面按钮。

仅在实际加载插件需要更新时，按已有授权保存并核验最新分层备份，正常关闭原稿、退出PS并确认原进程结束，然后启动新会话恢复并核对分层内容。原稿恢复或正常退出未知时保留保护，不重发。固定原生脚本的顶层编译拒绝须同时核对完整包装、请求身份、代码散列及返回错误；先完整归档并读回原未知记录，再分类为未开始，保留原失败，其他未知不沿用此判断。

实际326／UXP103共12组通过，8位渐变／描边共6组通过，范围与未验项目见[原生颜色数值](NATIVE-COLOR-CHANNELS.md)。
